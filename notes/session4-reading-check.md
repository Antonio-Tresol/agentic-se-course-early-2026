# Week 4 reading check: towards agent-first SE

A questionnaire to confirm people actually read the Week 4 material. It covers all six prework items:

1. Software Engineering at the Tipping Point (Adam Bender, Google, talk)
2. Effective Harnesses for Long-Running Agents (Anthropic)
3. Harness Engineering: Leveraging Codex in an Agent-First World (OpenAI, Ryan Lopopolo)
4. An Open-Source Spec for Codex Orchestration: Symphony (OpenAI)
5. Harness Engineering: Humans Steer, Agents Execute (Ryan Lopopolo, AI Engineer London, talk)
6. Agentic Software Engineering: Foundational Pillars and a Research Roadmap (Hassan et al., SASE)

Twenty-four questions across six sections, roughly twenty-five minutes. The multiple-choice questions catch a skim; the short-answer ones are the real signal, since they cannot be answered from general knowledge of coding agents. The OpenAI harness post (item 3) and the Lopopolo talk (item 5) are the same author on the same nine-month project, so they share one section; the talk adds a framework and operational detail the post leaves implicit, and the questions are fair to anyone who consumed either. The answer key is at the bottom; cut it before handing this out. The instructor can also select a subset of sections.

## Answer key

**1. b.** "Software ecology is the holistic study of the socio-technical ecosystems that produce software." (Bender, Tipping Point.)

**2. b.** A patch in the monorepo propagates to every application within a week, but shared fate is a trade-off: production systems deliberately avoid the dangerous kinds (cascading failures, one cluster infecting a region). (Bender, shared fate.)

**3. c.** The dependency graph grows quadratically with codebase size, so a 10x larger codebase can mean 100x (or more) tests to run when you test all dependencies. (Bender, testing and version control.)

**4.** Amplification has size but no direction: AI gives you more of whatever you already do, good or bad. It does not choose where the output goes. So a team with solid fundamentals amplifies good practice, and a team without fundamentals amplifies chaos. The implication is that fundamentals (decision-making culture, code health, release hygiene, security posture) decide whether AI helps or hurts. (Bender, citing DORA.)

**5. b.** An initialiser agent sets up a structured environment; a coding agent then makes incremental, one-feature-at-a-time progress while leaving clean artefacts for the next session. (Anthropic, Effective Harnesses.)

**6. c.** "By 'clean state' we mean the kind of code that would be appropriate for merging to a main branch." (Anthropic, Effective Harnesses.)

**7.** Any two of: a JSON feature list with pass/fail status; a session-by-session progress log (claude-progress.txt); git commits as a recovery and progress trail; an init.sh that standardises dev-server startup. Editing or removing tests is unacceptable because it could mask missing or buggy functionality, defeating the verification the harness depends on. (Anthropic, Effective Harnesses.)

**8. b.** Zero lines of manually-written code, every line generated by Codex; the motto is "Humans steer. Agents execute." (OpenAI, Harness Engineering.)

**9. c.** A short AGENTS.md (around 100 lines) used as a table of contents that points into a structured docs/ directory, giving the agent progressive disclosure. The "one big AGENTS.md" failed because context is scarce, too much guidance becomes non-guidance, monolithic manuals rot, and a single blob is hard to verify mechanically. (OpenAI, Harness Engineering.)

**10. b.** The agent reviews its own changes, requests further local and cloud agent reviews, responds to feedback, and loops until all agent reviewers are satisfied. (OpenAI, Harness Engineering.)

**11.** Human time; human and model attention; and the model context window. (Lopopolo talk.)

**12. c.** "...a failure of the harness to provide enough context around what it means to continue to completion." (Lopopolo talk.)

**13.** The repository itself (its docs, custom lints, structural tests, and review agents) plays the role of the static-analysis and optimisation passes: it constrains which code is acceptable to build, the way LLVM's passes shape Rust compilation. Swapping one model for another is like changing the code-generation backend (for example LLVM to cranelift): the constraints stay the same, the generated output differs. He confirms the related view that code is a disposable build artefact. (Lopopolo talk.)

**14. b.** A written spec (SPEC.md) that turns a board like Linear into a control plane for coding agents; the core idea is "for every open task, guarantee that an agent is running in its own workspace." (OpenAI, Symphony.)

**15. b.** Human context-switching. Engineers could comfortably manage only three to five interactive Codex sessions before context-switching cost dominated, so Symphony lets agents pull work from the tracker instead. (OpenAI, Symphony.)

**16. c.** "Treating agents as rigid nodes in a state machine doesn't work well. Models get smarter and can solve bigger problems than the box we try to fit them in." They moved towards assigning objectives rather than strict transitions. (OpenAI, Symphony.)

**17.** Any two of: (1) run the coding agent only in the per-issue workspace path (validate cwd == workspace_path before launch); (2) the workspace path must stay inside the workspace root, rejecting any path outside it; (3) the workspace key is sanitised so only [A-Za-z0-9._-] is allowed, replacing other characters with underscore. (OpenAI, Symphony, safety invariants.)

**18. b.** Actors, processes, artefacts, tools. (SASE.)

**19. b.** The Agent Command Environment (ACE) for the human coach, and the Agent Execution Environment (AEE) for the agents. (SASE.)

**20. b.** The paper reports a median PR completion time around 13 minutes alongside a large share of "plausible" fixes introducing regressions, and notes rigorous retesting dropped GPT-4's solve rate from 12.47 percent to 3.97 percent: the "speed vs trust" gap. (SASE, section 3.)

**21.** Three of the six activities: BriefingEng; Agentic Loop Engineering (ALE); AI Teammate Mentorship Engineering (ATME); Agentic Guidance Engineering (AGE); AI Teammate Lifecycle Engineering (ATLE); AI Teammate Infrastructure Engineering (ATIE). Or three of the artefacts: BriefingScript; LoopScript; MentorScript; Consultation Request Pack (CRP); Merge-Readiness Pack (MRP); Version Controlled Resolution (VCR). (SASE.)

**22.** A reasonable mapping (any correct version counts). Anthropic harnesses: a concrete answer to Bender's "intellectual control" and context-window strain, using init.sh, a feature list, and a progress log so work survives across sessions. OpenAI harness engineering: a concrete answer to the code-review and slop bottleneck Bender predicts, moving review to agent-to-agent and encoding taste as mechanical lints. Symphony: a concrete answer to Bender's "human attention is the most precious resource", turning the board into a control plane so humans manage work rather than supervise sessions. (Cross-source synthesis; Bender is strategic, these are tactical.)

**23. b.** Anthropic uses a minimal two-agent split (initialiser plus coding agent); Symphony runs many parallel agents off a Linear board; SASE proposes hybrid teams of specialised agents. (Cross-source synthesis.)

**24.** The post states the behaviour "depends heavily on the specific structure and tooling of this repository and should not be assumed to generalize without similar investment, at least, not yet." The disclaimer hinges on the project being greenfield: they started from an empty git repository with no human-written code to anchor the system. (OpenAI, Harness Engineering.)
