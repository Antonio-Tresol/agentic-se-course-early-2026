  1. Question 1 of 5 · choice

    What is "context rot" as described in context engineering for AI agents?

    Context rot refers to the finding that, as the number of tokens in the context window increases, the model's ability to accurately recall information from that context decreases. Context is a finite resource with diminishing marginal returns, and models have an attention budget that every new token depletes, so unnecessary tokens should be avoided.

    Source: Effective context engineering for AI agents (opens in a new tab), section "Context rot".

  2. Question 2 of 5 · choice

    Under the Model Context Protocol (MCP) architecture, which three core primitives can an MCP server expose to an agent client?

    MCP defines three core primitives that servers can expose: Tools (executable functions that AI applications can invoke to perform actions), Resources (data sources that provide contextual information, such as file contents or database records) and Prompts (reusable templates that help structure interactions with language models).

    Source: Model Context Protocol Architecture, "Primitives" (opens in a new tab).

  3. Question 3 of 5 · choice

    How does loading instructions via an Agent Skill differ from placing them directly in a project's root instructions file (such as CLAUDE.md or AGENTS.md)?

    Root instruction files load their full contents into context on every session launch, consuming a permanent portion of the attention budget. Skills only expose metadata initially and load their full instructional body on demand when invoked for a relevant task.

    Source: Claude Code Docs, "Skills" (opens in a new tab) and OpenAI Codex Docs, "Build skills" (opens in a new tab).

    Running a side task in a subagent keeps verbose intermediate output, such as extensive search results, build logs, or exploratory file reads, out of the primary conversation. The subagent executes within its own isolated context window and returns only the concise summary or finished artefact to the main agent.

    Source: Claude Code Docs, "Create custom subagents" (opens in a new tab). Also in OpenAI Codex Docs, "Subagents" (opens in a new tab).

  5. Question 5 of 5 · short answer

    Compare your answer with this one.

    Context compaction takes a conversation nearing the context window limit, summarises its contents in a high-fidelity way, and reinitiates a new context window with that summary so the agent can continue with minimal performance degradation. The risk of overly aggressive compaction is losing subtle but critical context whose importance only becomes apparent later, so the art lies in choosing what to keep and what to discard.

    Source: Effective context engineering for AI agents (opens in a new tab), section "Compaction".
