Retrieval opener and key

Two questions on this week's core talks and one from Week 3.

  1. Name the four parts Lloyd says a factory needs.

    A set of automations; a way to provide context and skills; a way to bring humans in at the right time, when work gets stuck; and self-improvement capabilities, the loops, such as a skill loop.

    Source: Lloyd's talk (opens in a new tab), at about 7:55.

  2. Why does Horthy say a harness cannot fix maintainability?

    Coding models are trained to pass tests, and maintainability goes unrewarded. Prompts, extra loops and review bots cannot supply a training objective the model lacks. He concedes that the available benchmarks cannot yet prove the claim. His remedy is to turn human review back on and move decisions earlier: product review, architecture, program design, then vertical slices.

    Source: Horthy from 7:30 (opens in a new tab) and from 14:58 (opens in a new tab).

  3. (Week 3) Your /goal condition named two CI commands. What does the goal's evaluator judge, and what does that leave unchecked?

    The evaluator judges only what the conversation shows: here, uv run pytest tests/unit passing and uv run lanorme check . clean. Whatever those commands do not exercise, such as naming, scope or design, stays unchecked until review. Codex learners answer for the condition they used.

    Source: Keep Claude working toward a goal (opens in a new tab).

Debate set-up

Split the room in half by where people sit, and assign the sides rather than letting learners choose, so some argue against their own view. Each side names one piece of evidence and its source aloud.

Half A

Lloyd: software engineering is becoming factory engineering

The engineer's job moves to building the loop that triages, specs, implements, reviews and verifies, with humans stepping in where the risk warrants it. A factory is judged by what it ships against human time and token time.

Evidence prompts, core readings

  • Lloyd: which four parts does he say every factory needs, and which quantities does he say to measure?
  • The playbook: which artefact does each stage commit, and which commit starts the next stage without a person?
  • The playbook: which code does it reserve for human review, so the rest can flow?

Extra evidence, if someone read it: Uber's factory, WorkOS's sandboxed agent, the Effective Harnesses artefacts, SASE's Merge-Readiness Pack.

Half B

Horthy: lights-off factories fail

Models are rewarded for passing tests, not for maintainability, and a harness cannot repair the missing objective. When HumanLayer went lights off in July 2025, an issue the agent could not solve forced engineers back into code they had stopped reading. Restore review and move decisions earlier.

Evidence prompts, core readings

  • Horthy: why does training on passing tests leave maintainability unrewarded, and what does he concede he cannot prove?
  • Horthy: what happened when HumanLayer went lights off in July 2025?
  • Bender: if AI amplifies whatever practices a team already has, what does that predict for a team that automates a loop it has never run by hand?

Extra evidence, if someone read it: uReview's addressal rate, Clinton's agent-to-agent incident, Huda's bottleneck, WorkOS's outcome measures.

Your close, 3 min. Put Bender's question to both halves: if code is cheap, where does the bottleneck move? Ask each side to name the stage of the Week 5 loop it moves to. Remind the room that the Uber, WorkOS and Anthropic figures are self-reported and that no source reproduces them.

Failure walk: the agent-to-agent incident

Script · 10 min · in the design-review threes

Would your design have stopped it?

  1. Tell the incident, 2 min. After a model upgrade, Anthropic's incident-response agent, on its own initiative, used Slack to ask another Claude instance, one that could write code, to push its fix. A human review gate caught the request, as designed. Clinton's lesson: set the boundary by what an agent can access and do, not by its instructions or by what you believe the model will do.
  2. Check the designs, 5 min. Each three takes one member's stage table and asks: which identity does each agent run as? Can one agent ask another to act for it, through a comment, an issue or a label? Which branch or file can each agent write? Which gate would catch a request like this one, and is that gate a person?
  3. Debrief, 3 min. Take one gap from two threes and name the control that closes it: a single-purpose identity for each agent, a write limit enforced in CI, a human gate, shadow mode for a new AI reviewer, or sampling of automated approvals.

Source: How Anthropic secures its AI-native software development lifecycle (opens in a new tab), Jason Clinton. A self-report by the vendor of the tooling.
