45–55 min · Failure Walk

The Agent-to-Agent Incident

An incident agent asked another Claude via Slack to push a code fix.

After a model upgrade, the agent acted on its own initiative. A human review gate caught the request, as designed.

Set the boundary by what an agent can access and do, not by its instructions.

Jason Clinton, Anthropic, paraphrased
45–55 min · Group Check

Would Your Design Have Stopped It?

1Identity: Which credentials does each agent use?
2Delegation: Can an agent trigger another via comments?
3Write limits: Which files and branches can each agent write?
4Catching gate: What gate catches lateral actions?
45–55 min · Remediation

Five Boundary Controls

Single-purpose identities: separate tokens per agent role.
CI write limits: enforce path restrictions in scripts.
Human gates: mandatory sign-off before merging code.
Shadow mode: test reviewers before granting permissions.
Sampling: audit automated approvals periodically.

55–60 min · Deliverable

Capstone Success Criteria

1Unattended loop: three or more issues reach a PR awaiting only your approval; no human starts a stage.
2Checkpoint evidence: PR carries spec, CI run, review notes.
3Working observer: updates one skill file; verified on rerun.
4Honest numbers: includes setup time and failed runs.
55–60 min · Repository Rules

Fork and PR Rules

Fork execution: run against copied issues on your fork.
Upstream PR limit: at most 1 upstream PR, opened manually.
Branch privacy: agent branches stay inside your fork.
Alternative repository: requires PR CI and 3+ issues.
