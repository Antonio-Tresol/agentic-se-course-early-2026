  1. Question 1 of 5 · short answer

    Compare your answer with this one.

    A check it can run that returns pass or fail, with a result it can read in the conversation: a test suite, a build exit code, a linter, a script that diffs output against a fixture, or a screenshot compared against a design. Claude then does the work, runs the check, reads the result and iterates until the check passes. Without one, you become the verification loop.

    Source: Best Practices for Claude Code, "Give Claude a way to verify its work" (opens in a new tab). Also in Claude Code in Action, on verification.

  3. Question 2 of 5 · choice

    When does the guide suggest skipping plan mode and asking Claude to make the change directly?

    Planning adds overhead. It pays off when you are unsure of the approach, when the change modifies several files, or when you do not know the code. A typo fix, a log line or a rename can go straight to implementation. The other two options are the cases where the guide recommends planning.

    Source: Best Practices for Claude Code, "Explore first, then plan, then code" (opens in a new tab). Also in Claude Code 101, on the Explore, Plan, Code, Commit workflow.

  4. Question 2 of 5 · choice

    Which of these does the guide list as a common mistake?

    When a task is complex, ambiguous or hard to describe well, the guide says to ask Codex to plan before it starts coding, for example in Plan mode (/plan or Shift+Tab), where it gathers context and asks clarifying questions first. The other three options are the guide's own advice: one chat per coherent unit of work, the default permissions while you are new, and durable rules in AGENTS.md or a skill rather than in the prompt.

    Source: Best practices (OpenAI Codex docs), "Common mistakes" (opens in a new tab) and "Plan first for difficult tasks".

  5. Question 3 of 5 · choice

    Which of these belongs in a project's CLAUDE.md?

    CLAUDE.md loads in every session, so it holds what Claude cannot infer from the code: commands it cannot guess, style rules that differ from the defaults, test instructions, repository etiquette and environment quirks. For each line, ask whether removing it would cause Claude to make mistakes; if not, cut it. The other three options are on the guide's list of things to leave out.

    Source: Best Practices for Claude Code, "Write an effective CLAUDE.md" (opens in a new tab). Also in Claude Code in Action, on keeping CLAUDE.md lean.

  6. Question 3 of 5 · choice

    Which of these belongs in a repository's AGENTS.md?

    A good AGENTS.md covers the repository layout, how to run the project, build, test and lint commands, conventions and PR expectations, do-not rules, and what done means and how to verify work. Keep it short and accurate: add rules only after you notice repeated mistakes, point to separate files for planning, code review or architecture, and use MCP for context that lives outside the repository and changes often.

    Source: Best practices (OpenAI Codex docs), "Make guidance reusable with AGENTS.md" (opens in a new tab) and "Use MCPs for external context".

  9. Question 5 of 5 · choice

    In Manual permission mode, which actions does Claude Code ask you to approve?

    Manual mode asks before actions that might modify your system. The last option describes auto mode, where a separate classifier model reviews most actions and blocks only what looks risky. Permission allowlists and sandboxing cut the number of prompts in either mode.

    Source: Best Practices for Claude Code, "Configure permissions" (opens in a new tab).

  10. Question 5 of 5 · choice

    Codex has two permission settings, approval mode and sandbox mode. What does sandbox mode determine?

    Sandbox mode sets whether Codex can read or write in the directory and which files it can access; approval mode decides when it asks for your permission to run a command. Model, reasoning effort and MCP servers are separate settings in the same configuration. If you are new to coding agents, start with the default permissions and loosen them only for trusted repositories or specific workflows.

    Source: Best practices (OpenAI Codex docs), "Configure Codex for consistency" (opens in a new tab).
